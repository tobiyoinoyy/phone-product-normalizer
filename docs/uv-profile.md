# 六面精裁与 UV 模板

六面精裁用于稳定裁切边界；UV 模板用于把不同照片放进同一套贴图坐标。两者独立：只裁掉透明边缘，不会自动消除拍摄尺度、位置或轮廓的差异。

## 输入与使用

一个文件夹对应一台手机，包含以下六面，每面一张 JPG 或 PNG。名称大小写不敏感，例如 `Front.JPG` 和 `front.png` 均表示 front；同一文件夹不要放两张同面的图片。

| 面 | 输入方向与处理约定 |
| --- | --- |
| front、back | 原图手机竖直；保持该方向 |
| top、bottom | 原图边框水平；保持该方向 |
| left | 原图边框水平；逆时针旋转 90° |
| right | 原图边框水平；顺时针旋转 90° |

这是本项目的拍摄约定，不是从任意图片自动判断面向或镜像。已经旋转过的六面成品，不应作为符合上述约定的原图重复输入。

只做精裁：

```bash
python -m phone_normalizer.uv_cli photos/sku1 --output-dir outputs/sku1
```

按内置模板对齐：

```bash
python -m phone_normalizer.uv_cli photos/sku1 \
  --output-dir outputs/sku1-uv \
  --uv-profile iphone12pro-user-crop-v1
```

按自定义数字模板对齐：

```bash
python -m phone_normalizer.uv_cli photos/sku1 \
  --output-dir outputs/sku1-uv \
  --uv-profile profiles/my-approved-profile.json
```

在已安装项目的 Python 环境中执行，完整参数见 `python -m phone_normalizer.uv_cli --help`。未指定 `--uv-profile` 时不自动选择机型模板。

结果目录包含六张小写文件名 PNG、`metadata/` 下的逐面处理记录，以及整组 `manifest.json`。缺面、重复面或已有同名输出会先报错；其他文件名不参与处理。处理中途失败时保留已完成的面并记录错误，重跑应选择新的输出目录。记录中的 `uv_fit_validation: not_performed` 表示尚未替用户在目标模型上试贴，不能把程序完成等同于 UV 验收通过。

## 内置模板的来源与范围

`iphone12pro-user-crop-v1` 将本轮用户认可的“2”版六面裁边记录为数字模板，固定输出尺寸如下，单位为像素，顺序为宽 × 高：

| 面 | 输出尺寸 |
| --- | --- |
| front | 957 × 1985 |
| back | 960 × 1986 |
| left | 104 × 1904 |
| right | 116 × 1877 |
| top | 1017 × 130 |
| bottom | 1046 × 112 |

这些尺寸服务于已经认可的贴图坐标，不是根据手机官方长宽生成的通用纹理规格。更换拍摄方向、镜头、工位、裁边习惯或 UV 布局后，应重新验证，必要时建立另一份模板。

认可的裁边包含少量向内裁切：并非所有不透明外沿都必须保留。模板按已确认的边界执行，不重新扩回原来的松散外接框。镜头凸起仍保留，圆角和凸起旁的透明区域也可能是正确结果；这份模板没有将所有侧面强制削成没有凸起的矩形。

模板只包含数值和处理约定，不包含参考照片、原图、私人路径或用户贴纸内容。另建模板时应沿用内置数字模板的结构，填写自身认可的坐标与裁切数据；不要把原图路径或图片数据塞进配置，也不要只改输出宽高就宣称获得了新的 UV 模板。

结构见 [内置 JSON](../phone_normalizer/profiles/iphone12pro-user-crop-v1.json)。每面记录参考精裁画布 `reference_size`、主体范围 `reference_body_bbox`、在该画布中的认可裁框 `crop_xyxy` 和整90°转向 `orientation_quarter_turns`（正数逆时针）。裁框右/下坐标不包含在内，输出宽高是右减左、下减上。主体范围可用 `phone_normalizer.uv_profile.body_bbox` 从已按约定定向的参考精裁 PNG 测量；认可裁框应来自用户对同一参考图的纯裁切。模板须含全部六面，不接受缺面或未知字段。

## 几何处理顺序

1. 使用唯一的 `BiRefNet_dynamic` 抠图，保守去支架并摆正。
2. 默认精裁以 alpha 阈值 128 定位边界，裁切框内保留连续透明度；随后按面向约定旋转左右侧面。
3. 启用模板时，根据手机主体边界对齐到模板参考坐标，再应用用户认可的裁切区域。这一步将主体位置与最终画布裁切分开处理。
4. 必要时执行受限的全局范围校正。该补偿须同时满足不超过 1 px 和不超过 1% 的限制，不用局部拉扯、填色或补画来追求轮廓重合。

默认推理最长边仍为 1024 px，CPU 与 MPS 都使用同一模型；推理的 alpha 恢复到原图坐标后再进行几何处理。1024 px 是推理上限，不是最终 PNG 的宽高。

## 保真与适用边界

处理保留来源照片的内容，不生成、涂抹或修补手机的瑕疵、镜头、按钮、贴纸和接口。旋转、缩放等几何变换会通过插值重采样，因此“保真”不代表变换前后每个像素数值完全不变。

主体轮廓对齐不等于所有部件语义对齐。照片中的镜头凸起、不同深度部件、拍摄透视、镜头畸变以及摆放差异，可能使按钮或镜头等局部位置仍有偏差。不要把按轮廓得到的结果宣称为所有语义锚点逐像素准确，也不能把一套模板推广为所有同型号手机的通用标准。

支架卡爪如果遮住机身，照片本身就缺少被遮挡内容。流程可保守清除外部支架，不能真实恢复遮挡部分；不要通过进一步削掉下框、贴纸或生成填补来隐藏这一限制。

## 检查结果

先检查六面齐全、方向正确、输出尺寸与选定模板一致，再以 100% 比例检查直边、圆角、镜头凸起、贴纸、接口、可见瑕疵和支架接触处。不同 SKU 的成色与颜色差异属于原图内容，不应被统一成参考照片。

将结果替换到目标模型后，检查轮廓、局部部件和接缝。文件尺寸一致、轮廓对齐或一次样张视觉认可，都不能替代这一步。固定画布中由凸起或圆角形成的透明区域无需一律清零；如有新增留白，应区分主体直边漂移和真实轮廓差异。

验证记录应区分正式代码回归、同源图片复现、跨 SKU 图片检查和实际 UV 试贴。本轮认可的样张提供了裁边依据；同一组原图重跑只证明复现，不增加跨 SKU 样本数。不得将这些记录写成已经验证所有 iPhone 12 Pro 的批量适配。

## 与旧入口的关系

`python -m phone_normalizer`、原 Python API 与 macOS GUI 保持兼容原行为。需要上述精裁或 UV 模板时，使用 `python -m phone_normalizer.uv_cli`；不要假设旧窗口已经启用了新模板。源图与认可参考始终保留，结果写入新的输出目录。
